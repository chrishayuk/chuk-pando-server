# Git feature support (stock git 2.54 client unless noted)

Verified by `tests/cg1.sh`, `tests/cg2.sh`, `tests/cg3.sh`, `tests/cg4.sh`, `tests/cg5.sh`
(modified client), `tests/cg6.sh`, `tests/features.sh`. "Yes" = covered by a passing test.

| Feature | Status | Notes |
|---|---|---|
| Smart HTTP, protocol v2 `ls-refs` (peel, symrefs, unborn, ref-prefix) | Yes | HEAD is a symref to `refs/heads/main` (trunk) |
| Smart HTTP, protocol v2 `fetch` (want/have/done, thin-pack, ofs-delta, no-progress) | Yes | negotiation recognises haves that are tips of ref versions |
| Protocol v0 / v1 upload-pack (multi_ack_detailed, no-done, side-band-64k, thin-pack, ofs-delta) | Yes | `-c protocol.version=0/1` |
| Clone empty repository | Yes | `unborn HEAD` advertised |
| Clone / fetch / pull (ff, --rebase), incremental fetch | Yes | `git fsck --full --strict` clean |
| `clone --bare`, `clone --mirror`, `clone --single-branch` | Yes | |
| Push new branch, update, force (`-f`), delete (`:ref`), `--force-with-lease` | Yes | compare-and-swap on old-id for every ref |
| `push --atomic` | Yes | one metadata transaction for all refs |
| `push --mirror`, `fetch --prune`, `push --dry-run` | Yes | |
| Push options (`-o`) | Accepted, ignored | |
| Ref directory/file conflicts (`a` vs `a/b`) | Rejected like git | `cannot lock ref … exists; cannot create …` (D15) |
| Ref name validation (`check-ref-format` rules) | Yes | "funny refname" |
| Concurrent pushes, same ref | Yes | exactly one winner, loser gets `! [remote rejected] … (cannot lock ref …)` |
| Concurrent pushes, different refs (1,000 branches) | Yes | no shared lock, 0 transaction conflicts |
| Tags: lightweight, annotated, nested annotated, `--follow-tags`, auto-follow, delete | Yes | peeled values in ls-refs / v0 advertisement |
| Trees with gitlinks (submodule pointers) | Yes | gitlinks are not dependencies |
| Large objects (tested 30 MB), chunked request bodies, gzip request bodies | Yes | objects are held in memory while decoding |
| `fetch.uriprotocols=http` → protocol v2 `packfile-uris` | Yes | every planned pack as a URI (covers, self-contained L0, on-demand thick twins of thin L0) from the cache nodes; empty inline pack |
| Parallel packfile-URI download + indexing (modified client `fetch.packfileUriJobs`, `no-ref-delta`) | Yes | |
| `explicit-haves` push (modified client) | Yes | trunk-only `.have`, named refs for update checks |
| `git fetch origin <sha>` (any object, protocol v2) | Yes | any object contained in a committed pack; the closure of the version that introduced it is sent |
| Partial clone `--filter=…` | No (falls back) | `filter` not advertised; git warns and does a full clone |
| Shallow clone/fetch `--depth N`, fetch into a shallow clone, deepen, `--unshallow` (protocol v2) | Yes | depth packs are generated by an object walk (not pack reuse); D12 |
| `--shallow-since`, `--shallow-exclude`, `--deepen` (relative) | No | clear `ERR … not supported` |
| Shallow over protocol v0/v1 | No | `shallow` not advertised in v0 |
| Shallow push (from a shallow clone) | No | rejected (`shallow pushes are not supported`) |
| Signed pushes (`--signed`, push certificates) | No | `push-cert` not advertised |
| `want-ref` (ref-in-want), `sideband-all`, `wait-for-done`, `object-info`, `bundle-uri` | No | not advertised |
| `include-tag` in fetch | Ignored | git's tag auto-follow backfill fetches the tags instead |
| Dumb HTTP | No | 403 |
| SHA-256 repositories | No | `object-format=sha1` only |
| Authentication / HTTPS | No | harness uses plain HTTP without auth; terminate TLS in front |
| `git archive --remote`, git://, ssh:// | No | HTTP only |
| Hooks, `receive.denyNonFastForwards`, protected branches | No | non-fast-forward updates are accepted when the old-id matches (git default) |
| Repository default branch other than `main` | No | trunk is `refs/heads/main` |
